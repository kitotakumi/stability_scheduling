## 1. ざっくり歴史：Path Relinking とは何か

- Path Relinking（PR）は、1990年代に Fred Glover によって提示されたメタヒューリスティクスで、**2つの良い解の間の軌道を系統的にたどり、中間解からさらに良い解を見つける**発想に基づく手法である。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]
- 文脈としては、**Tabu Search / Scatter Search の intensification（集中化）と diversification（多様化）を橋渡しする手法**として発展してきた。[https://www.sciencedirect.com/science/article/pii/S0305054821001441][https://leeds-faculty.colorado.edu/glover/SS-PR%20Template.pdf]
- PR の基本思想は、**高品質解どうしは重要な属性を共有していることが多く、その間の経路にも有望解が存在しやすい**というものである。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]

### PR の基本動作
- 始点解 `s` から目標解 `t` に向かって、
- `t` が持つ属性を `s` に少しずつ導入し、
- 各ステップで「目標解に近づく候補ムーブ」を作り、
- その中から次の中間解を選ぶ、という流れで進む。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]

### 研究上の位置づけ
- 単独法として使うだけでなく、PR は **GA, Memetic Algorithm, GRASP, ILS, Tabu Search, Ant Colony** などとハイブリッド化されてきた。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]
- したがって PR は、「主役の探索法」でもあり得るが、実務上はむしろ**既存探索法の補強器（intensification operator）**として使われることが多い。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]

## 2. スケジューリング問題での適用

PR はスケジューリングでも広く使われており、特に**順列表現・機械順序表現**を持つ問題と相性がよい。

### 代表的な適用先
- **Job Shop Scheduling Problem (JSP)**  
  PR を組み込んだ手法として、GRASP+PR や TS/PR が報告されている。[https://mauricio.resende.info/doc/pargjss.pdf][https://arxiv.org/abs/1402.5613]
- **Flexible Job Shop Scheduling Problem (FJSP)**  
  2024年のレビューでも、**Scatter Search + PR** が代表的手法の一つとして位置づけられている。[https://www.sciencedirect.com/science/article/pii/S037722172300382X]
- **Multi-objective Flexible Job Shop Scheduling**  
  PR は Tabu Search と組み合わせた形でも使われている。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]
- **Bi-objective flowshop** など、他のスケジューリング系問題でも PR の利用例がある。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]

### JSP における代表例
- Peng, Lü, Cheng の **TS/PR for JSP** は、ベンチマークに対して高い競争力を示し、**205インスタンス中49個で上界改善、さらに20年以上未解決だった1例を解いた**と報告している。[https://arxiv.org/abs/1402.5613]

### スケジューリングで PR が向いている理由
- 解が「ジョブ順序」「機械ごとの処理順序」のような**属性集合**として自然に表せる。
- 良い解どうしが部分的に似た順序構造を持つことが多く、**その共通構造を壊しすぎずに探索できる**。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]

## 3. JSP での PR 方法論の整理

## 3.1 何を「属性」とみなすか
JSP/FJSP では、PR の「属性」は普通は以下のいずれかになる。

- 機械ごとのジョブ列
- オペレーションの相対順序
- 割付 + 順序（FJSP の場合）

あなたの研究では、**機械ごとの作業順序**を解表現にしているため、PR の属性もここに置くのが自然。

---

## 3.2 ムーブの作り方

PR では「目標解へ近づくムーブ」をどう作るかが設計の中心になる。

### (A) direct swap 型
**定義（本メモでの呼称）**  
目標解で位置 `i` にあるべきジョブ `j*` を、現在解のその機械列の中から探し、**その位置まで一気に swap で持ってくる**。

- これは、順列表現に対して「目標解との不一致位置を1つ直す swap」を選ぶ方式とみなせる。
- PR の一般論としても、順列表現では「現在解を目標解に近づける swap」をムーブとして定義するのは自然である。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]

**長所**
- 1回で「ある位置を目標解と一致」させられる。
- 距離減少が明確。
- 実装が単純。
- 反応時間が厳しい再スケジューリングに向く。

**短所**
- 1回の変更がやや大きい。
- JSP では swap 後の順序が**閉路を作る可能性**があるため、N5 と違って feasibility check が必要。

---

### (B) adjacent swap 型
目標ジョブを**隣接 swap を繰り返して**寄せていく方式。

**長所**
- 1手あたりの変化が小さい。
- 安定性破壊を細かく制御しやすい。

**短所**
- パスが長くなる。
- 候補評価回数が増えやすい。
- 即応性が必要な再スケジューリングでは重くなりやすい。

---

### (C) insertion 型
あるジョブを抜き取り、別位置に挿入して目標解へ近づける方式。  
multi-objective PR の整理論文でも、**first insertion / last insertion** は problem-based heuristic として整理されている。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]

**長所**
- 順列表現では強力なことが多い。
- swap より少ない手数で目標順序へ近づける場合がある。

**短所**
- 1回の move で複数の相対順序を同時に変える。
- あなたの「順位変更量ベース」の安定性指標との対応が、direct swap よりやや読みづらい。

---

### (D) shift 型
要素をずらして目標解へ近づける方式。  
これも permutation 向けの problem-based heuristic として整理されている。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]

---

## 3.3 候補の選び方

PR のもう1つの設計軸は、「作った候補の中から何を選ぶか」。

### 文献上の代表分類
- **ランダム選択**[https://www.sciencedirect.com/science/article/pii/S0305054821001441]
- **単一目的で最良選択（pure）**[https://www.sciencedirect.com/science/article/pii/S0305054821001441]
- **重み付き和（aggregation combined）**[https://www.sciencedirect.com/science/article/pii/S0305054821001441]
- **Pareto 非劣候補から選択**[https://www.sciencedirect.com/science/article/pii/S0305054821001441]
- **decomposition-based**[https://www.sciencedirect.com/science/article/pii/S0305054821001441]

### 本研究との対応
あなたの研究はすでに
- 安定性 `D`
- メイクスパン `MS`
- 重み `λ`
- min-max 正規化  
を使う設計になっているので、**PR の候補選択も aggregation combined（重み付き和）で統一するのが最も自然**。

## 4. 本研究での適用方針

以下は、あなたの現在の研究（再スケジューリング、安定性重視、ILS ベース）に合わせた、最も自然な PR の入り方。

## 4.1 PR をどこに入れるか
現状の構成は
- 局所探索：N5 山登り
- 摂動：insert / swap
- 目的：安定性 `D` と `MS` の重み付き和
- 将来的に「初期解へ戻す」操作として PR を検討  
という流れだった。

したがって PR の役割は、**新しい大域探索器ではなく、ILS 内の“制御された摂動 / 回帰操作”**として入れるのがよい。

### 推奨する位置づけ
- `局所最適解 x` に到達
- `x` が元スケジュールから離れすぎたとき、
- `初期スケジュール S_p` を guiding solution にして PR をかける
- 経路上で見つかった最良中間解を次の探索の出発点にする

つまり、

> **「壊しすぎた構造を、全部戻すのではなく、良い点だけ残して少し戻す」**

という使い方。

---

## 4.2 direct swap 採用理由

本研究の初版 PR では、**direct swap を第一候補**にするのが合理的。

### 理由1：安定性指標と整合的
あなたの安定性は、**ジョブの投入順序・順位変更量**を直接見ている。  
direct swap は「目標解のある位置を一致させる」操作なので、**順位差の縮小と move の意味が対応しやすい**。

### 理由2：実装が最も明快
各機械について
- 不一致位置を見つける
- そこに来るべきジョブを探す
- swap する  
だけで候補が作れる。  
AI に実装させるときも誤解が少ない。

### 理由3：候補数が制御しやすい
各ステップの候補数は基本的に  
**「全機械の不一致位置数の総和」**  
になるので、adjacent swap より膨れにくい。

### 理由4：再スケジューリングの即応性に合う
あなたの計算機実験では、GA より ILS の方が短時間で良い結果を出している。  
その流れでは、PR も**細かすぎる adjacent swap より、短い経路を作れる direct swap の方が親和的**。

### 理由5：初期実装として比較しやすい
現状すでに摂動として `insert / swap` を持っているため、  
PR はまず **direct swap で最小実装**し、その後に
- adjacent swap PR
- insertion PR
- hybrid PR  
と比較すればよい。

---

## 4.3 注意点
- N5 は「閉路を作らない」ことが知られているが、**PR の一般 swap はその保証がない**。したがって、**候補ごとに実行可能性チェックが必要**。
- あなた自身のスライドでも、PR を入れる場合は**実行可能解チェックのコスト検証が必要**としていた。この点は本質的な注意点。  
- したがって、本研究における PR は **“安定性に優しいが、評価は重い可能性がある補助操作”** と位置づけるべき。

## 5. 本研究向けの具体アルゴリズム案（AI実装用）

## 5.1 役割定義
- **Initiating solution**: 現在の局所最適解 `S_cur`
- **Guiding solution**: 外乱前の初期スケジュール `S_ref = S_p`
- **出力**: PR 経路上で見つかった最良中間解 `S_best`

---

## 5.2 解表現
- 解は**機械ごとのジョブ列**で表す。
- 各機械 `k` について列 `seq[k] = [j_1, j_2, ..., j_n]` を持つ。

---

## 5.3 距離（差分集合）
各機械 `k` に対して、不一致位置集合を

\[
\delta_k(S,T)=\{ i \mid seq_S[k][i] \neq seq_T[k][i] \}
\]

とする。

全体の候補ムーブ集合は、この不一致位置の全組から作る。

---

## 5.4 候補生成（direct swap）
各機械 `k`、各不一致位置 `i ∈ δ_k(S,T)` に対して：

1. 目標解 `T` で位置 `i` にいるべきジョブ `j* = seq_T[k][i]` を取得
2. 現在解 `S` の機械 `k` の列の中で、`j*` がいる位置 `q` を探す
3. `seq_S[k][i]` と `seq_S[k][q]` を swap
4. 得られた解 `S'` を候補に追加

これで、少なくとも位置 `i` は目標解に一致する。

---

## 5.5 候補評価
各候補 `S'` について：

1. **実行可能性チェック**
   - 閉路が出るなら棄却
   - あるいはガントチャート再生成／スケジュールデコードで評価可能なら採用

2. **メイクスパン計算**
   - 既存の評価器（Taillard のアルゴリズム or ガントチャート再生成）を使う

3. **安定性計算**
   - 既存の順位変更量ベース安定性関数 `D(S_p, S')` を使う

4. **総合スコア**
   - あなたの既存目的関数と揃えて  
   \[
   F(S') = \lambda \hat{D}(S_p,S') + (1-\lambda)\hat{MS}(S')
   \]
   を使う  
   （`\hat{D}`, `\hat{MS}` は min-max 正規化後）

5. **次の中間解選択**
   - `F(S')` が最良の候補を次状態に採用

---

## 5.6 終了条件
以下のいずれかで停止：

- 目標解 `S_p` に到達
- 候補が1つも作れない
- 最大ステップ数 `L_max` 到達
- 改善なしが `stall_limit` 回続く
- 時間制限到達

---

## 5.7 戻り値
**最終到達解ではなく、経路上の最良解 `S_best` を返す**のがよい。  
PR は途中で一時的に悪化してもよいが、最終的に使いたいのは「経路上のベスト」である。[https://www.sciencedirect.com/science/article/pii/S0305054821001441]

---

## 5.8 擬似コード

```pseudo
function PATH_RELINKING_DIRECT_SWAP(S_cur, S_ref, lambda, L_max):
    S = S_cur
    S_best = S_cur
    F_best = evaluate_weighted(S_cur, S_ref, lambda)
    ...（省略）
```

## 6. 実装と実験結果（2026-04 実施）

### 6.1 実装の概要

設計書 5.1〜5.7 に基づき、`ils_scheduling.py` に `path_relinking()` メソッドを実装した。

**実装仕様:**
- **Initiating solution**: ILSの現在の最良解 `S_cur`
- **Guiding solution**: 外乱前の初期スケジュール `S_ref = S_p`
- **ムーブ**: direct swap（各機械の各不一致位置について、目標解の要素を現在位置と swap）
- **候補選択**: 全候補を `evaluate()` で評価し、スコア最良を次状態に採用（greedy best selection）
- **実行可能性チェック**: `build_gantt()` が `None`（閉路=実行不能）を返す場合、`evaluate()` が `inf` を返すため自動的に棄却
- **戻り値**: 最終到達解ではなく、経路上の最良解 `S_best` を返す
- **終了条件**: 目標解到達 / 候補なし / `L_max` 到達 / `stall_limit` 回改善なし
- **PR+LS**: PRの各ステップ後に N5 局所探索を適用するオプション（`ls_strategy` パラメータ）も実装

**ILS統合:**
ILSの `run()` に `path_relink_mode` パラメータを用意。有効にすると、主摂動で `relink_trigger` 回停滞した時点で PR に切り替え、PR の経路上最良解を受理判定にかける。

### 6.3 実験2: PRの内部動作の診断

PR が効かない原因を特定するため、ILS を 200 反復ウォームアップした後に PR を単発実行し、経路上の各ステップを詳細にトレースした。3問題（mt10_delay60, la36_delay148, la40_delay148）×2重み×3seed×2摂動 = 36 ケース。

**典型的なトレース（mt10_delay60, w=0.95, seed=7, swap ウォームアップ後）:**

```
Step | MS    | Stab  | Score  | Diffs | Improved
init |  1051 |  5.99 | 0.9469 |    13 |
   1 |  1060 |  5.56 | 0.9872 |    11 |          ← 1歩目でMS +9悪化
   2 |  1076 |  5.72 | 1.0606 |    10 |          ← MS +25悪化
   3 |  1077 |  5.22 | 1.0642 |     9 |
   4 |  1122 |  3.80 | 1.2672 |     7 |          ← MS 大幅悪化
   5 |  1122 |  3.29 | 1.2663 |     6 |
   6 |  1080 |  2.09 | 1.0723 |     4 |
   7 |  1080 |  0.67 | 1.0697 |     2 |
   8 |  1080 |  0.00 | 1.0685 |     0 |          ← 初期解に到達
```

**全36ケースの傾向:**
- swap→PR: 受理 3/18（改善幅は微小、Stab で最大 -1.10）
- insert→PR: 受理 4/18（同上、最大 -0.43）
- 実行不能候補（閉路）の発生率: 0%（全候補が実行可能）
- **全ケースで PR の 1 歩目からスコアが悪化。経路上に出発点より良い解が存在しない。**

### 6.4 実験3: PR+LS（局所探索併用）の検証

PR の各中間解から N5 局所探索で MS を回復させる方式を検証した。4問題（mt10_delay60, la21_delay147, la36_delay148, la40_delay148）×2重み×3seed×2摂動 = 48 ケースで PR 単体と PR+LS(best) を比較。

#### 6.4.1 毎ステップ LS（初期実装・失敗）

最初の実装では、PR の各ステップ直後に LS を実行していた。しかしこの方式は構造的な問題があった:

1. PR が 1 つの不一致位置を初期解方向に戻す → MS が悪化
2. LS が N5 近傍で MS を最適化 → PR が戻した位置を再び元に戻す
3. 結果として出発点と同一の解に戻る
4. 次の PR ステップの出発点が元に戻るため、同じ swap を繰り返す

**結果:** PR 単体と完全に同一の結果。LS が PR の変更を即座に打ち消すため、PR が前に進めない。

#### 6.4.2 経路完了後に最良中間解へ LS（修正版）

毎ステップ LS の問題を踏まえ、PR の経路を最後まで走りきった後、**経路上で最もスコアがマシだった中間解**（出発点より悪いが他の中間解よりは良い解）に対して LS を 1 回だけかける方式に修正した。

この方式の狙い: 中間解は「数箇所が初期解方向に戻された状態」でMS が悪化している。LS がこの中間解を改善する際、**戻した位置をそのまま元に戻すのではなく、N5 近傍の別の経路で MS を回復**できれば、安定性改善分を保持できる。

**結果:**
- PR+LS で追加改善（PR 単体では不可だが PR+LS で改善）: **2/48**
  - la36 insert→ seed=107 w=0.95: St=4.88→4.81（MS=1620 維持）
  - la36 insert→ seed=107 w=0.8: St=4.88→4.81（MS=1620 維持）
- PR 単体で改善していたケースでは PR+LS も同一結果: **11/48**
- 残り 35 ケース: PR 単体と同一（改善なし）

PR+LS の意図した効果（中間解から別経路で MS 回復しつつ安定性を保持）は la36 で確認できたが、発生頻度・改善幅ともに限定的。

---

### 6.5 原因分析

PR が機能しない根本原因は以下の構造的なトレードオフにある。

#### (1) ILS の最良解は「MS 最適化のために初期解から離れた構造」を持つ

ILS の局所探索（N5 近傍）は MS を改善するために機械順序を変更する。最良解で初期解と異なる位置（不一致位置）は、**MS を最良値にするために必要な変更**であり、どの 1 つを初期解方向に戻しても MS が悪化する。

mt10_delay60 での不一致は 13 位置。これらは全て MS 改善に寄与しており、安定性のために「戻しても MS が壊れない不要な変更」が存在しない。

#### (2) direct swap は MS 悪化を回避できない

direct swap は「初期解の位置 i にあるべきジョブを現在位置に持ってくる」操作であり、本質的に MS 最適化の成果を壊す。ムーブの種類（swap/insert/adjacent swap）を変えても、初期解方向への移動が MS 悪化を伴う点は同じ。候補選択を greedy からランダムに変えても、全候補が MS 悪化を伴う以上、選び方で改善は生まれない。

#### (3) greedy best selection は「最もマシな悪化」を選ぶだけ

全候補が出発点より悪いため、候補選択は改善ではなく「最小の劣化」の選択になる。経路全体を通じて出発点を上回る解が存在しない。

#### (4) LS による MS 回復は大半のケースで PR の変更を打ち消す

LS が PR の中間解を改善する際、PR で戻した位置を再び元に戻すのが最も効率的な MS 回復であるため、安定性改善分が消えるケースが大半。LS が別経路で MS 回復できる場合（la36 の例）に限り、安定性改善が保持される。

---

### 6.6 結論

本研究の再スケジューリング問題においては、ILS の最良解と初期スケジュールの間に「MS を維持しつつ安定性を改善できる中間解」が存在しないため、direct swap 型 PR は有効に機能しない。これは PR のムーブ設計や候補選択の問題ではなく、**MS 最適化と安定性（初期解との近さ）が本質的にトレードオフ関係にある**ことに起因する構造的な問題である。

PR+LS（経路上最良中間解に LS 適用）は原理的に正しいアプローチであり、一部のケース（la36）で改善効果を確認できた。しかし、大半のケースでは LS が PR の変更を打ち消すため、改善頻度・改善幅ともに限定的であった。

PR が有効となるためには、「初期解方向に戻しても MS が悪化しない冗長な順序変更」が最良解に含まれている必要があるが、N5 近傍による局所探索は既にそのような冗長性を除去した解を出力するため、PR が改善の余地を見出せない。

insert 摂動は PR なしでも安定性の良い解に到達しやすく、PR の補助を必要としない。ILS 単体（特に insert 摂動）の性能向上を優先する方が、研究成果として有望である。

---

### 6.7 他の解法との組み合わせに関する考察

今回の結果は「PR が一般に効かない」ことを示すものではなく、**ILS（N5 局所探索）との組み合わせにおいて効かなかった**ことを示すものである。PR が効かなかった根本原因は「N5 局所探索が解の冗長性を徹底的に除去する」点にあり、この性質を持たない解法と組み合わせれば状況が変わる可能性がある。

#### GA との組み合わせが有望な理由

GA の解は交叉・突然変異で生成されるため、N5 局所探索ほど厳密に MS 最適化されていない。つまり**「初期解方向に戻しても MS が悪化しない冗長な順序変更」が解に残っている可能性が高い**。PR はこのような冗長性を利用して安定性を改善する手法であるため、GA の出力解に対しては効果を発揮できるかもしれない。

また、GA の集団内には多様な解が存在するため、初期解を目標にしなくても「安定性が良い個体 → MS が良い個体」の間で PR を適用し、両者の良い属性を組み合わせた中間解を探すという使い方も考えられる。文献上でも Scatter Search + PR は FJSP の代表的手法として位置づけられている。

#### ILS の N5 局所探索が特殊である点

N5 近傍は「クリティカルブロック端の swap のみ」という非常に小さく狙い澄ました近傍であり、閉路チェック不要という理論的保証を持つ。この性質のおかげで高速かつ高品質な局所最適解に到達できるが、副作用として**解から冗長な順序変更を徹底的に除去する**。PR が拾える「MS を壊さずに安定性を改善できる余地」がこの過程で消失している。

より大雑把な局所探索（例: ランダム insert ベースの山登り）や局所探索を経ていない解（GA の生の出力、GRASP の構築解など）に対しては、PR が有効に機能する余地が残る。

#### 今後の展望

- **GRASP + PR**: GRASP は毎回異なる greedy 構築解を作るため、解のバリエーションが豊富で PR との相性が良い。JSP における GRASP+PR の先行研究もある。
- **Memetic Algorithm（GA + LS）内の PR 的交叉**: GA の交叉オペレータとして PR を使い、親個体間の経路上で有望な子個体を生成する手法。
- **Elite pool 間の PR**: 複数回の独立実行で得た良質解を Elite pool に蓄積し、pool 内の解同士で PR を適用する方式。ILS でも複数回実行の結果に対してなら効果が出る可能性がある。

### 6.8 クリティカルパスと不一致位置の関係

#### 6.8.1 実験: 不一致位置はクリティカルパス上か？

ILS の最良解における初期解との不一致位置が、クリティカルパス（CP）上にあるか否かを調べた。5問題×2重み×3seed = 30ケース。

| Problem | 不一致数 | CP上 | CP外 | CP外の割合 |
|---------|---------|------|------|-----------|
| mt10_d60 | 13-14 | 0 | 13-14 | **100%** |
| mt10_d90 | 12-14 | 0 | 12-14 | **100%** |
| la21 (w=0.95) | 10 | 6 | 4 | 40% |
| la21 (w=0.8) | 4 | 2 | 2 | 50% |
| la36 | 10-21 | 2-8 | 8-13 | 52-67% |
| la40 | 4-14 | 2 | 2-12 | 50-86% |

**mt10 では不一致の 100% がクリティカルパス外であった。** la36, la40 でもCP外が過半数を占める。

#### 6.8.2 解釈: なぜCP外の変更を戻してもMSが悪化するのか

この結果は「不一致は全てMS改善に寄与している」という前提の再検討を促す。CP上の操作を変更しないとMSは改善しないのだから、CP外の変更は一見MSに無関係に見える。

しかし実験結果が示す通り、CP外の不一致を初期解方向に戻してもMSは悪化する。これは以下のメカニズムによる:

1. **CP外の弧の向きを変えても元のCPの長さは変わらない** — これはディスジャンクティブグラフの理論から正しい
2. **しかし弧の向きが変わることで新しいパスが生まれ、そのパスが元のCPより長くなりうる** — CPが移動してMSが悪化する

つまり「MS改善のためにはCPを操作する必要がある（真）」と「CP外を操作してもMSは改悪しない（偽）」は異なる命題である。後者は成り立たない。

#### 6.8.3 N5局所探索による間接的な最適化

N5近傍はCPのブロック端のswapのみを行うが、その副作用としてスケジュール全体のタイミングが連鎖的に変化する。CP上の操作を改善すると、ジョブ制約を通じてCP外の操作のstart timeも変化し、それが別の機械に波及する。

この過程で、CP外の操作順序も「現在のCPを支える」構造に間接的に最適化される。結果として、ILSの最良解ではCP外の変更も含めて全ての順序が MSを間接的に支えており、どの1つを戻してもMSが悪化する解が生成される。

この「N5局所探索がCP外の順序まで間接的に固定してしまう」という性質が、PRが効かない根本的な理由であり、CP外のみを修正するPRでも効果が出ないことを説明する。

### 6.9 既存解からの安定性修復に関する展望

PRの実験を通じて得られた知見は、「ILSの最良解からpost-hocに安定性を修復する」アプローチ全般の困難さを示している。しかし、PR以外の方法も含めてスコープを広げると、以下のアプローチが考えられる。

#### (A) 安定性制約付き局所探索

ILSの局所探索自体に安定性の制約を組み込む。「初期解との不一致数がN以下の近傍のみ受理」「安定性がK以上悪化する近傍は棄却」など。post-hocの修復ではなく、**探索中に安定性の悪化を予防する**アプローチ。

- 利点: MSを壊してから戻す非効率を回避。MS/Stabのトレードオフを探索中にリアルタイムで制御
- 欠点: 探索空間が制限されてMS改善が頭打ちになるリスク

#### (B) 重み付き目的関数のチューニング

現在の重み付き和 `λ * Stab + (1-λ) * MS` の重みを探索の段階に応じて動的に変化させる。序盤はMS重視 (λ小) で効率的な解を見つけ、終盤はStab重視 (λ大) に切り替えて安定性を改善。

- 利点: 既存のフレームワーク内で実装が容易
- 欠点: 終盤のStab重視フェーズが、6.8.3で述べた「CPの間接支持構造」を壊さずにStabを改善できるかは不明

#### (C) 多目的局所探索 (Pareto Local Search)

MS改善とStab改善を別々の近傍で行い、パレートフロントを近似する。MS改善にはN5近傍、Stab改善には安定性指向の近傍（初期解方向へのinsert等）を使い分ける。

- 利点: MS/Stabのトレードオフを明示的に探索できる
- 欠点: 計算コストが増大。ILSの単純さ・高速性という利点が薄れる

#### (D) insert摂動の安定性指向チューニング

insert摂動が既にPRなしで安定性の良い解に到達しやすい（実験で確認済み）ことを活用し、insertの挿入先を「初期解の順序に近づく方向」に偏らせる。完全なPRではないが、摂動に安定性方向のバイアスをかける。

- 利点: 既存のILSフレームワークに最小限の変更で導入可能
- 欠点: バイアスが強すぎると摂動の多様性が失われ、旧PR実装のgreedy化失敗と同じ問題を起こす

#### (E) 安定性aware なN5フィルタリング

N5近傍の中から「MS改善量が同等なら安定性が良い方を優先する」辞書式選択を行う。最良改善の近傍選択時に、MS改善量が閾値以内なら安定性で選ぶ。

- 利点: N5の理論的保証を維持しつつ、安定性を考慮した探索が可能
- 欠点: 現在の重み付き評価関数が既にこの役割を果たしているはず。効果が出るかは重みの設定次第

#### 評価

上記のうち、(A) と (D) が最も有望と考える。(A) は「MSの間接支持構造を壊さないまま安定性を確保する」唯一の方法であり、(D) は既に効果が確認されている insert 摂動の延長線上にある。(B) は実装コストが低いため試す価値がある。(C), (E) は現段階では優先度が低い。

いずれのアプローチも、本研究で明らかになった「N5局所探索がCP外の順序まで間接的に固定する」という知見を踏まえた設計が必要である。

### 6.10 距離定義と近傍構造の本質的議論

#### 6.10.1 絶対位置ベースの距離の問題

本実装の direct swap は、解間の距離を「機械ごとの各位置でジョブが一致するか」（絶対位置ベース）で測っている。しかし JSSP では、スケジュールの構造を決めるのは「どのジョブがどのジョブの前に処理されるか」という**相対順序（離接アークの向き）**である。

例: 機械M0上で `[A, B, C]` → `[B, A, C]` を比較すると:
- **絶対位置ベース**: pos0, pos1 が不一致 → 差分=2、direct swap 1回で修正
- **離接アークベース**: ペア(A,B)の向きだけ異なる → 差分=1

絶対位置ベースでは、同じ構造変化を過大にカウントする場合がある。またdirect swapで「位置iを一致させる」ことは、離接アーク空間では複数のペアの向きを同時に変える可能性があり、意図しない大きな構造変化を引き起こしうる。

JSSP における2つのスケジュール間の真の距離は、**向きが食い違っている離接アークの数**として定義する方が理論的に正確である。

#### 6.10.2 離接アークベースにした場合の変化

PRのムーブを「ペア(X,Y)の相対順序を初期解に合わせる」に変更すると:
- 各ステップの変化が最小単位（1ペアの向き反転）になる
- 経路がより細かくなり、MS悪化が軽減される可能性がある
- 候補数はペア数（各機械で O(n^2)）になり、計算コストが増える

ただし、6.8.3 の知見（CP外の離接アークを変えてもMSが悪化しうる）は離接アークベースでも同様に成り立つ。距離の測り方が正確になっても、「MS維持とStab改善を両立する1手が存在しない」という構造的問題は解消しない。

#### 6.10.3 問題の帰着: 安定性指向の近傍構造

PRの議論も、2フェーズ探索（効率性→安定性）の議論も、結局は**「安定性を改善する近傍をどう定義するか」**という問題に帰着する。これはPRにおけるムーブ戦略と同義である。

現状で判明していること:
1. **N5近傍**: MS改善方向にしか動けない。安定性改善の手段にはならない
2. **direct swap（絶対位置ベース）**: 安定性は改善するがMSを壊す。1手でMS維持＋Stab改善を実現できない
3. **離接アーク反転**: direct swapより細粒度だが、同じ構造的問題を抱える
4. **LS内蔵型（PR+LS）**: 安定性方向の1手＋N5 LSのMS回復を1操作とみなす。一部のケースでのみ有効

**1手の近傍操作でMS維持＋Stab改善を実現することは、ILSのN5最良解に対しては構造的に困難である。** これはN5局所探索がCP外の順序まで間接的に固定する性質（6.8.3）に起因する。

#### 6.10.4 帰結: post-hoc修復 vs 探索中の制御

上記の分析から、「ILSの最良解を得た後にpost-hocで安定性を修復する」アプローチは、近傍構造をどう定義しても本質的に困難であるという結論に至る。

より有望な方向は、**探索中に安定性を制御する**アプローチである:
- 目的関数の重みで MS/Stab のバランスを調整（現在の実装で既に可能）
- 局所探索中に安定性制約を課す（6.9 (A)）
- 摂動に安定性バイアスを入れる（6.9 (D)）

これらは「MSを壊してから戻す」のではなく「最初からMS/Stabバランスの良い領域を探索する」方針であり、6.8.3の構造的制約を回避できる。

本研究で明らかになった以下の知見は、JSSP再スケジューリングにおける安定性改善の研究全般に寄与する:
- **N5局所探索はCP外の順序まで間接的に固定する**（6.8.3）
- **CP外の操作を変更してもMSは悪化しうる**（6.8.2）
- **ILSのN5最良解に対しては、MS維持＋Stab改善の1手操作が存在しない**（本節）
- **post-hoc安定性修復は近傍構造の定義に依らず構造的に困難**（本節の帰結）

### 6.11 best/current分離＋悪化受理による再検証（2026-04-14 実施）

#### 6.11.1 背景と動機

6.1〜6.6 の実験では、PRの経路上最良解が出発点より常に悪いため受理されず、ILSは PR 前と同じ解から再出発していた。つまり**PRの結果が探索に反映されていなかった**。

この問題を解消するため、ILSの受理判定を以下のように再設計した:

1. **`best`（全体最良解）と `current`（探索出発点）を分離**。`best` は絶対に悪化しない。`current` は停滞時に悪化方向にも移動する。
2. **通常摂動は `current` から出発**（旧: `best` から）。
3. **停滞判定**: `stagnation_threshold`（デフォルト30）反復 best が改善しなければ停滞と判定。
4. **停滞時のPR結果**: `current` に無条件受理。PRは `best` から初期解方向に経路を辿り、経路上最良の中間解を `current` にセットする。そこからILSの通常ループ（摂動→LS）を再開する。
5. **停滞時の通常摂動結果**: `best_score * (1 + δ)`（δ=0.05）以内なら `current` に受理。δを超えていれば棄却。

この設計により、PRの中間解（安定性方向に数歩戻った状態）からILSが再出発し、別の局所最適解に到達する可能性が生まれる。

#### 6.11.2 実験設定

5問題（mt10_delay60, mt10_delay90, la21_delay147, la36_delay148, la40_delay148）×2重み（w=0.95/0.05, w=0.8/0.2）×5seed×6手法。各ILSは500反復。

| 手法 | 摂動 | 悪化受理 | PR | 備考 |
|------|------|---------|-----|------|
| ILS_swap | swap | なし | なし | ベースライン（改善のみ受理） |
| ILS_swap_stag | swap | δ=0.05 | なし | 停滞時に悪化受理のみ |
| ILS_swap_PR | swap | δ=0.05 | trigger=50 | 停滞時に悪化受理＋PR |
| ILS_insert | insert | なし | なし | ベースライン |

#### 6.11.4 分析

**(1) 悪化受理（_stag）の効果: MS方向の多様化**

悪化受理は `current` を別の盆地に移動させることで、探索空間の広い範囲をカバーする。

- **la36 で顕著な効果**: insert_stag が w=0.95 で MS=1604（ベースライン 1619 から -15）と大幅改善。ただし標準偏差が大きく（±18.7）、安定性も悪化（St=12.85）。w=0.8 でも MS=1612 と改善傾向。
- **mt10 系では逆効果**: 悪化受理により MS が悪化するケースが発生（swap: 1051→1054, insert: 1067→1071）。
- **la21, la40 ではほぼ変化なし**: ベースラインが既に安定した解に到達しており、悪化受理の効果が出にくい。

悪化受理は大きい問題（la36）で探索空間の広さが活きるが、小さい問題（mt10）では安定した局所最適解から離れるデメリットが上回る。

**(2) PR追加（_PR）の効果: 限定的**

PR を悪化受理に追加した場合の効果を、悪化受理のみ（_stag）と比較する:

- **insert_PR vs insert_stag**: insert_PR は複数の問題で安定性が微改善（mt10_d90 w=0.95: 7.44→6.65, la21 w=0.95: 11.64→11.12）。ただし同時にMSが悪化する傾向もある。
- **swap_PR vs swap_stag**: ほぼ差がないか、微小な変化のみ。
- **la40**: swap_PR が St=4.85 を達成（swap ベースライン 5.95 から改善）。ただし insert ベースラインが既に St=4.85 であり、PR 固有の効果とは言い難い。

PRの「初期解方向に戻す」効果は、悪化受理による一般的な多様化効果に埋もれてしまい、PR 特有の改善として検出できるケースはごく少数であった。

**(3) insert 摂動が依然として最も有効**

全設定を通じて、insert 系の手法が swap 系を上回る傾向は変わらない。la21 では insert 系が MS=1462 と swap 系の MS=1500 を大きく上回り、la36 でも insert_stag が最もMSの良い解を発見している。

#### 6.11.5 考察: なぜ best/current 分離でもPRの効果が出にくいのか

best/current 分離により PR の中間解から ILS が再出発できるようになったが、PRの効果は依然として限定的である。これは以下の理由による:

1. **PR の中間解は「初期解方向に数歩戻った状態」であり、MS が悪化している**。そこから LS を走らせると、N5 近傍は MS を回復する方向に動き、PR が戻した位置を再び元に戻す力が働く。結果として、PR なしの悪化受理と同じような盆地に到達しやすい。

2. **悪化受理（_stag）は PR の上位互換として機能する**。悪化受理は `current` をランダムな方向に動かすため、PR の「初期解方向」という特定の方向に限定されない。探索の多様化としては、方向を限定しない悪化受理の方が広い探索が可能。

3. **PR の方向性（初期解に近づく）は目的関数で既に考慮されている**。重み付き評価関数 F = λ·Stab + (1-λ)·MS は安定性を内包しているため、通常の ILS 探索自体が安定性を考慮した解を見つけるようになっている。PR による「意図的な安定性方向への移動」は、目的関数による暗黙的な誘導と重複する。

### 6.12 PRに関する最終結論

6.1〜6.11 の一連の実験と分析を通じて、以下の結論に至った。

#### ILS＋N5局所探索に対するPRの限界

本研究の再スケジューリング問題において、direct swap 型 Path Relinking は ILS（N5局所探索）との組み合わせでは有効に機能しない。この結論は、以下の段階的な検証を経て確立された:

1. **基本実装（6.2）**: PR 追加の効果は限定的。
2. **内部動作診断（6.3）**: PR の 1 歩目からスコアが悪化し、経路上に出発点より良い解が存在しない。
3. **PR+LS（6.4）**: LS が PR の変更を打ち消し、大半のケースで効果なし。
4. **構造分析（6.8）**: N5 局所探索が CP 外の順序まで間接的に固定するため、MS 維持＋Stab 改善の 1 手操作が存在しない。
5. **best/current 分離（6.11）**: PR の中間解から ILS を再出発させても、PR 特有の改善効果は悪化受理による一般的な多様化効果に埋もれる。

根本原因は**N5 局所探索の性質**にある。N5 は CP のブロック端のみを操作する小さく狙い澄ました近傍であり、高品質な局所最適解を高速に生成するが、副作用として解から冗長な順序変更を徹底的に除去する。PR が拾える「MS を壊さずに安定性を改善できる余地」がこの過程で消失する。

#### 研究上の意義

この「ネガティブな結果」は以下の点で学術的に有用である:

- **N5 局所探索が CP 外の順序まで間接的に固定する**という知見は、JSSP の解構造に関する新しい理解を提供する。
- **post-hoc 安定性修復は近傍構造の定義に依らず構造的に困難**という結論は、再スケジューリングにおける安定性改善の研究方針に指針を与える。
- ILS＋N5 という特定の組み合わせにおける PR の不適合を示したものであり、GA や GRASP など N5 局所探索を経ない解法との組み合わせでは状況が異なりうる（6.7）。

#### 今後の方向性

PR の結果を踏まえ、ILS ベースの研究としては以下の方向が有望である:

1. **insert 摂動の安定性バイアス（6.9 (D)）**: insert 摂動が既に安定性の良い解を出しやすいことが確認されている。挿入先を初期解の順序に寄せるバイアスを加えることで、PR 的な効果を摂動レベルで実現できる可能性がある。
2. **ILS の多様化機構の改善**: best/current 分離＋悪化受理は、PR なしでも探索の多様化に寄与する。特に大きい問題（la36）で効果が確認された。この機構のパラメータ調整（δ, stagnation_threshold）による改善の余地がある。
3. **VNS（Variable Neighborhood Search）への拡張**: swap/insert を複数の近傍として体系的に切り替える VNS 的な制御構造は、ILS の摂動制御の自然な拡張である。

### 6.13 評価軸変更による再評価の余地（2026-04-19 追記）

6.1〜6.12 の判断は **重み付きスカラー値（F = λ·Stab + (1−λ)·MS）のみ**を評価軸として行ったものである。その後、本研究は評価方法論を多目的（Pareto front / HV / 差分 EAF / conditional HV）に拡張しており（`evaluation_design.md`）、PR の扱いは以下の理由で**再評価の対象**となる。

#### スカラー優位性 ≠ Pareto 貢献度

- PR の中間解は、ある特定重み λ における scalar 値では出発点より悪化することが多い（6.3 の知見）。
- しかし MS–Stab 平面で見ると、**その中間解は既存 Pareto front に対して非劣**である可能性がある。
  - 例: 中間解が「MS やや悪化・Stab 大幅改善」の場合、特定重みでは劣位でも Pareto への寄与（HV 増分）は正。
- 重み付きスカラーは Pareto 平面の 1 方向の射影に過ぎないため、scalar 改善なし = Pareto 非貢献 とは結論できない。

#### 再評価の枠組み

コア実験（実験 1）で整備する以下の道具立てをそのまま PR にも適用できる。

- 多 weights 掃引 + per-trial Pareto 抽出 + union Pareto
- HV（full / conditional）, C-metric
- 差分 EAF（PR あり vs PR なし）

これらで **PR が Pareto 平面のどこかで貢献しているか**を直接測る。特に低 stab 領域の conditional HV と 差分 EAF が PR 再評価の主指標になる。

#### 適用先の候補

- **GA + PR**: 集団ベース手法との組み合わせは、6.12 で示唆した未検証の方向（N5 局所探索を経ないため状況が異なりうる）。
- **ILS + PR（評価軸変更のみ）**: LS が PR の変更を打ち消す構造問題は残るが、稀に Pareto 寄与する中間解が出る可能性は否定できない。最小限の追加実装で検証可能。
- **PR 単独 → 多目的評価**: PR で得られる経路全体を Pareto として評価する純粋な多目的 PR の枠組み。

#### 位置付け

優先度は実験 1（コア比較）の完了後。本命の主張 (A)〜(D) を先に固め、余力があれば「先行判断のスカラー限定評価は Pareto 評価で覆りうる」という方法論的な findings として追加する。
