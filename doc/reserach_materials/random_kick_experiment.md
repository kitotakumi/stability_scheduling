# ランダムキック対照実験（内的妥当性）— 正直な記録

> **本実験は国際学会版の論文には載せない**（理由は末尾）。本ディレクトリは生データと正直な解析記録を保全するためのもの。修論版での考察収録を検討する。

## 1. 目的

Memetic+PR / Memetic+repair の **高安定 HV 利得**が、

- (a) $S_p$（外乱前スケジュール＝最安定の極）**方向への誘導**によるものか、
- (b) 収束した集団を揺さぶる**一般的な多様化**によるものか、

を切り分けるための対照実験。**同強度・ランダム方向のキック**（repair と同じ深さ分布の direct swap を、方向だけランダム化したもの）を `memetic_random` として追加し、`memetic_ls`（無キック）→ `memetic_random`（多様化のみ）→ `memetic_repair`/`memetic_pr`（S_p 誘導）の3段で利得を分解する。

## 2. 結論（要約）

**当初の強い主張「高安定利得は $S_p$ 方向の誘導に固有・ランダムでは高安定フロントに届かない」は、正しい正規化で測り直すと支持されない。**

1. **高安定 HV 利得の大半は「多様化」**（無キック `ls` → `random` の大ジャンプ）。
2. **$S_p$ 誘導の上乗せ（`random` → 機構）は小さい**——la21 でほぼゼロ、la36L で小（+0.003, ただし δ=1.0 で一貫）。
3. 明確に残る差は **計算コスト約 7 倍**（random は $S_p$ から遠くへ飛ぶため、キック後の局所探索の再収束が高コスト。repair/PR は $S_p$ を狙うので安い）。
4. ⇒ 機構の価値は「品質に必須」ではなく「**同等の高安定品質を、構造化ターゲットにより効率的に達成する**」点にある。

## 4. ⚠️ 解析上の2つの落とし穴

`diagnostics/random_kick_control.py` をそのまま使うと**誤った結論**になる。実際、素朴な解析では「repair ≫ pr・random は高安定に届かない」と出るが、これは下記2点のアーティファクトである。

1. **正規化(make_norm)と P50 を、その問題 dir 内の4手法だけから再計算する。** main_v1 は全7手法×10重みから正規化を作るのに対し、対照 dir には GA/ILS が無く効率重みも間引かれているため、正規化アンカーが非整合になる（HV 値も手法間の大小も歪む）。
2. **random のコスト都合で4重みに間引いたことが memetic_pr の高安定被覆を過小評価する。** 例: mt10 の pr 高安定は **4重みだと 0.021 だが、全10重み（main_v1）では 0.044 ＝ repair と同じ**。repair は4重みでも0.044で安定。pr が高安定を埋める重みが間引きで漏れている。

→ **正しい比較は「main_v1 の norm + P50 に random を置いて、同一4重みで測る」。** 以下は補正版。

## 5. 補正版の結果（main_v1 の norm + P50, 4重み）

### 5.1 高安定 HV（D<P50）の分解

| 問題(リスケ率) | ls(無キック) | random(多様化) | repair | pr | **多様化** (ls→rand) | **S_p誘導** (rand→機構) |
|---|---|---|---|---|---|---|
| la36L (73%) | 0.0148 | 0.0296 | 0.0328 | 0.0327 | **+0.0148** (p=.001, δ=+1.0) | repair +0.0032 / pr +0.0031 (p=.001, δ=+1.0) |
| mt10 (72%) | 0.0121 | 0.0286 | 0.0437 | 0.0210 † | **+0.0165** (p=.005, δ=+.64) | repair +0.0151 (p=.014, δ=+.82) / **pr は random に負け (ns)** † |
| la21 (35%) | 0.0290 | 0.0607 | 0.0613 | 0.0613 | **+0.0317** (p=.001, δ=+1.0) | repair/pr +0.0006 (p=.008/.016, δ≈+.65) |

† mt10 の pr は §4 の4重み間引きで過小評価（全10重みの main_v1 では pr = repair = 0.044）。よって mt10 の「pr が random に負ける」は protocol アーティファクトであり、アルゴリズムの差ではない。

**読み**: どの問題でも `ls → random` の多様化ジャンプ（+0.015〜0.032）が `random → 機構` の誘導上乗せ（+0.0006〜0.003、mt10-repair のみ +0.015）より大きい。高安定利得の主因は多様化。

### 5.2 統合 HV（参考, 同 norm / 4重み, 中央値）

| 問題 | ls | random | repair | pr |
|---|---|---|---|---|
| la36L | 0.876 | 0.925 | 0.919 | 0.912 |
| mt10  | 0.607 | 0.627 | 0.638 | 0.616 |
| la21  | 0.970 | 1.012 | 0.946 | 1.022 |

→ 統合 HV は random ≈ repair ≈ PR（三者とも ls には勝つ）。**統合 HV 上の「+機構 > 無機構」利得はほぼ多様化効果**で、S_p 方向は統合 HV にはほぼ寄与しない。

### 5.3 計算コスト（total_cpu_time, 秒/run）

| 問題 | ls | repair | pr | random | **random / repair** |
|---|---|---|---|---|---|
| la36L | 74.8 | 301.9 | 509.4 | 2196.4 | **7.3×** |
| mt10  | 21.1 |  78.4 | 128.2 |  200.8 | **2.6×** |
| la21  | 17.6 |  71.1 | 119.0 |  134.0 | **1.9×** |

→ random は同強度でも repair の **1.9〜7.3 倍**のコスト（規模・リスケ率が大きいほど顕著）。構造化ターゲット $S_p$ への移動はキック後 LS が安い。

## 6. 妥当性チェック: run 自体は正しい

mt10 の `memetic_pr` / `memetic_repair` の最終解 (MS, D) は **main_v1 と完全一致**（同一シード・決定的）。run に問題はなく、§4 の見かけの差は解析正規化と重み間引きに起因する。

## 8. なぜ学会版に載せないか

- 元の役割は「機構の高安定利得は $S_p$ 方向に固有（多様化では届かない）」の論拠だったが、**実データはこれを否定**した（多様化主因・差はコスト）。
- 残る効率（7×）の話は副次的かつ半ば構成上自明（$S_p$ を狙えばキックが小さく LS が安い）。
- tight な国際学会論文では、この対照を載せると「検証対象だった強い主張」を自分で弱めることになり割に合わない。**「$S_p$ 方向が品質に必須」という主張自体を撤回すれば、対照実験は不要**になる（H2 の非対称＝機構 vs 無機構の比較は random 対照なしで robust に立つ）。
- 隠蔽ではない：検証対象の主張をしなくなるため、対照を省くことは整合的。**修論版**では本記録に基づき「多様化主因＋効率＋小さな一貫上乗せ」を考察として収録を検討する。

## 9. 強度マッチング修正版（2026-09-20, mt10）

§4-§5 の対照は、ランダム側の摂動強度キャップを**現在解の n_diff（=S_p からの距離）**から取っていた。これは S_p 方向キック（n_diff を縮める→cap 自己制限）とランダム方向（n_diff を縮めない→cap 増大）の間に**非対称な正のフィードバック**を生み、§5.3 のコスト比較（1.9〜7.3倍）を歪めていた（発散の主因はこの設計であり、キック後 LS の再収束コスト自体の差ではない、と誤解される余地があった）。

**修正**: `kick_mode='random_matched'`（`memetic_scheduling.py`）を追加。深さ k の抽選元を現在状態から切り離し、main_v1 の `memetic_repair` 実測深さ分布（重みごとの経験分布, `mt10_repair_depth_pools.json`）から引く。mt10・main_v1 の全10重み・n=10 で再実行（`results/random_kick_control_matched/`）。

**強度マッチング監査**: 全重みで要求深さ比 1.00〜1.01、実適用とのミスマッチ 0.0%（mt10 は小規模で swap がほぼ常に実行可能なため早期打ち切りが発生しない）。フィードバックは完全に遮断されている。

**結果（main_v1 の norm+P50, 全10重み）**:

| 指標 | ls | random_matched | repair | pr |
|---|---|---|---|---|
| 高安定HV (D<P50=20) | 0.0121 | 0.0336 | 0.0437 | 0.0437 |
| 統合HV(中央値) | 0.732 | 0.758 | 0.745 | 0.773 |
| CPU中央値(s/run) | 20.4 | 170.9 | 72.3 | 121.9 |

- **高安定HV: repair/pr が random_matched を完全分離で上回る**（δ=+1.0, p=0.001, 両方）。強度を揃えてもなお方向に実質的な効果が残る。§5.1 の「pr が random に負ける（mt10, †注記）」は重み間引きの人為的産物だったことが確定（pr=repair=0.0437 で main_v1 全重み値と一致）。
- **利得の分解**: 多様化(ls→random_matched) +0.0215（68%）、方向誘導(random_matched→repair/pr) +0.0101（32%）。§2 の「大半は多様化」という要約は方向を過小評価しており、方向の寄与は無視できない規模。
- **統合HVは3手法で区別不能**（§5.2 の結論はそのまま維持）。
- **計算コスト比は 7.3倍 → 2.36倍（中央値）に縮小するが、消えない**（重み別レンジ 1.85〜3.06倍）。強度を完全一致させても残るため、原因は §5.3 が推測していた「S_p から遠くへ飛ぶ→再収束が高コスト」という**着地点の性質そのもの**であり、キャップ設計の副作用ではない。これは PR/repair が guiding solution を S_p に固定する設計上の根拠（§3.3 相当: 経路の中間解が両端点の構造を継承し着地点を壊さない）と直接整合する。

**結論の更新**: §2④「機構の価値は品質に必須ではなく効率」はやや不正確だった。正しくは——**方向誘導は高安定領域を埋めるための必要条件ではない（ランダムでも実質量が届く）が、(i) 同深さでも品質がなお有意に高く、(ii) 同深さでのコストが2〜3倍安い。二重の意味で支配的（dominant）**。実装: `src/ils_scheduling.py`（`_perturb_random_swap` に実適用数記録を追加）, `src/memetic_scheduling.py`（`kick_mode='random_matched'`), `experiments/core_comparison_v3/diagnostics/random_kick_control_matched.py`。

## 10. 2シナリオ目: la36S（2026-09-20）

la36S（ρ=27%, Memetic-LS が高安定HVで完全にゼロ=median 0.0000）で同じ強度マッチング手順を再実行（main_v1 の repair 実測深さ分布から抽選、全10重み・n=10）。

**注記（運用事故）**: 実行中に PC がスリープ（S0モダンスタンバイ）に入り約7時間中断。プロセス自体は生存し中断点から再開したため MS/D の結果に影響はないが、`total_cpu_time`/`history[*].cpu_time`/`uea_points_t` は `time.time()`（壁時計）で測っているためスリープを跨いだ5 run（当時実行中だった5並列ぶん: `w08_02/t009`, `w09_01/t000〜t003`）だけ値が破損（正常~230s→~25,100s）。該当5ファイルを削除し同一コマンドで再計算（resume機構で残り95本はスキップ、seed決定的なので MS/D は同一値に再現）。**時間計測がスリープに対して脆弱な点は把握済み**（`time.process_time()` 未使用が原因）で、main_v1 等の過去データもスリープを跨いだ run があれば同じ穴を持つ可能性がある(通常運用ではスリープ抑制のため未発生の見込み)。

**強度マッチング監査**: 全重みで要求深さ比 1.00、ミスマッチ0.0%。

**結果（main_v1 の norm+P50, 全10重み）**:

| 指標 | ls | random_matched | repair | pr |
|---|---|---|---|---|
| 高安定HV (D<P50=16) | 0.0000 | 0.0563 | 0.0800 | 0.0794 |
| 統合HV(中央値) | 0.888 | 0.959 | 0.992 | 0.991 |
| CPU中央値(s/run) | 26.7 | 186.6 | 111.5 | 166.8 |

- **高安定HV: repair/pr が random_matched を完全分離で上回る**（δ=+1.0, p=0.001, mt10と同じ完全分離）。Memetic-LS は高安定領域に事実上ゼロだが、方向なしの同強度キックでも到達量は repair/pr の約70%止まり(0.0563 vs 0.0800)。
- **統合HVでも方向効果が有意に検出される**（δ=+1.0, p=0.001）。mt10（統合HVは3手法区別不能）との違いは、la36S は無キックで高安定領域に実質ゼロのため、方向誘導の効果が統合HVにも透けて見えるためと考えられる（無キックの下駄が非ゼロの mt10 では統合HVの大部分を占める効率帯の寄与に埋もれる）。
- **計算コスト比 1.67倍**（mt10の2.36倍より小さい。la36Sは規模が小さく摂動後LSの再収束コスト差自体が縮むためと考えられる）。

**2シナリオ(mt10, la36S)を合わせた結論**: 高安定HVでの方向誘導の完全分離優位（δ=+1.0, p=.001）は2シナリオで再現し頑健。「利得の大半は多様化」という§2の要約は撤回し、**「方向誘導は高安定領域を埋める必要条件ではないが、同深さでも品質が有意に高く、コストは常に1.7〜2.4倍安い＝二重に支配的」**を確定結論とする。統合HVへの波及はシナリオ依存（無キック時の高安定到達量がゼロに近いほど統合HVにも滲み出る）という追加の所見が得られた。
