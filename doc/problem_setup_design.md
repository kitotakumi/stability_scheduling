# 問題状況設計ドキュメント

> **目的**: コア実験で使用するベンチマーク問題・外乱設計の方針と根拠を整理する。
>
> **改訂 (2026-06-02)**: 当初の「外乱大小（単一遅延の大きさで難易度を作る）」方針を、実測・理論・文献調査にもとづき**撤回**した。スケール（難易度）軸を **問題規模** に一本化している。経緯は §3 を参照。

---

## 1. 設計方針

本研究の貢献の核心は「探索構造の分析」であり、**ミクロ分析**が価値の源泉である。

### 1.1 外乱注入の2系統と本研究の立場

動的JSPの先行研究には、外乱の与え方に大きく2系統ある。

| 系統 | 代表研究 | 外乱の与え方 | 「外乱大小」の作り方 |
|---|---|---|---|
| **シミュレーションベース** | Zhang, Gao & Li (2013) | プランニングホライズン上に Poisson 到着・指数分布故障を**ストリーム**生成。周期＋イベント駆動で繰り返しリスケ | 到着率 λ（sparse/dense）・新ジョブ数（20→200）・故障レベル Ag |
| **固定イベントベース** | Kundakcı & Kulak (2016) | 決まった外乱イベントを固定時刻に与え、単一／少数のリスケ点で評価 | （外乱大小は独立変数化せず）**問題規模**（op数 small/medium/large） |

本研究は**再現性と因果分析の精度を最優先するミクロ分析**である。ストリームの確率的揺らぎは因果の特定を妨げるため、**固定イベントベース**を採用する。具体的には：

- **単一リスケジューリングポイント**（外乱イベント1個）で評価する
- 外乱は**作業遅延のみ**に限定する（routing 固定のまま順序調整で対処）
- 外乱シナリオを固定して再現性を担保する

### 1.2 二目的（効率・安定性）

効率＝makespan、安定性＝元スケジュール $S_p$ からの逸脱。重み付き和で評価し、重み掃引でパレートフロントを描く。安定性関数は現状 `evaluation.py` の**機械上ジョブ順位の偏差**を使用（`Σ|init_pos − cur_pos|/(cur_pos+1)^1.25`）。

> 安定性指標を文献標準の「開始時刻偏差」に替える案も検討したが、効率↔安定の**コンフリクト**は外乱構造（後述の headroom）で決まり指標選択では作れないため、コア問題の解決策にはならない。比較可能性・フロント密度の観点で将来採用しうるが、本設計では現状指標を継続する。

## 2. ベンチマーク問題 ＝ スケール軸

### 問題数: 4問題

| 問題 | サイズ | 特性 |
|---|---|---|
| mt10 | 10×10 | 古典的ベンチマーク。小規模・構造が単純 |
| la21 | 15×10 | 中規模。既存パイロット実験の実績あり |
| la36 | 15×15 | 中大規模。既存パイロット実験の実績あり |
| la40 | 15×15 | 大規模。la36 と同サイズだが構造が異なる |

**位置づけ**: §3 の通り、本研究では**問題規模そのものがスケール（難易度）軸**である。op数で mt10(100) < la21(150) < la36/la40(225) と段階的にカバーし、スケール依存性を確認する。la36 と la40 の比較で「同サイズでも構造が異なれば結論が変わるか」を検証する。

**問題数をこれ以上増やさない理由**: アルゴリズムの構造的主張（ILS vs Memetic の適合性、PR/repair の相互作用）は問題サイズよりアルゴリズム構造に由来する。

## 3. 「外乱大小」を作らない理由（旧方針の撤回）

当初は「単一遅延の大きさ $\delta$ で外乱スケール（小・大）を作る」方針だった。しかし以下の実測・理論・文献調査により、**固定イベント・単一遅延の枠組みでは外乱大小が独立な難易度軸として成立しない**ことが判明したため撤回する。

### 3.1 難易度の本質は headroom

**headroom** ＝ `RSR_makespan − 最適化後makespan`。
RSR（Right-Shift Rescheduling＝元順序のまま右にずらすだけの素朴な修復）に対し、**順序を並べ替えてどれだけ makespan を縮められるか**を表す。

- `headroom = 0` → 右シフトが既に makespan 最適。並べ替える価値なし → **どの手法も同じ解に収束し区別不能（縮退シナリオ）**。
- `headroom 大` → 並べ替えに価値があり、良い手法ほど多く縮める → **手法間の差が出る**。

すなわち headroom ＝ **アルゴリズム（ILS / Memetic / PR）が差を出せる土俵の広さ**そのものである。

### 3.2 実測：δ も遅延箇所数も headroom を動かさない

| シナリオ | 外乱 | 再スケ対象op | **headroom** |
|---|---|---|---|
| mt10_delay60 → delay90 | 単一遅延 δ +50% | 70 → 70 | **0 → 0** |
| la36 単一delay148 | +120 | 89 | **26** |
| la36 multi3 / multi5 | +242（3/5箇所） | 89 / 89 | **26 / 26** |

遅延量を増やしても、遅延箇所を増やしても headroom は不変。mt10 に至っては headroom=0 の**縮退ベンチ**。

### 3.3 理論：単一クリティカル路遅延 ＝ 定数の右シフトオフセット

クリティカルパス上の遅延は、再スケ問題に対して「**全体を一定量だけ右にずらす**」効果しか持たない。RSR も最適解も同じ $\delta$ を吸収するため、両者の差＝headroom は $\delta$ に不変。「時間軸で $S_p$ から遠い」ことと「探索空間（順序の並び）で最適解が遠い」ことが、単純遅延では**完全にデカップル**する。

複数遅延も臨界路上に置く限り一様シフトの重ね合わせで同じ。また**非フレキシブルJSPでは作業遅延と機械故障は同一ファミリー**である（別機械に逃がせず「待つ＋並べ替える」のみ。稼働中opを止める故障は preempt-resume で「そのopの処理時間を故障時間ぶん延長」と等価）。したがって故障時間を severity に振っても結論は同じ。

### 3.4 headroom を動かす唯一のレバー＝外乱の「位置」、しかしそれは問題規模と同義

外乱の**位置（早い/遅い）**を変えると headroom は動く（la21 で全クリティカルopを走査すると **0→119**）。しかしその headroom は **再スケジュール対象op数（＝問題のどれだけを再最適化するか）と強く相関**する。早い外乱＝再スケ範囲が広い＝headroom大、遅い外乱＝範囲が狭い＝headroom小。

すなわち**「外乱大」は実質「再最適化する問題サイズが大きい」**ことであり、固定イベント・単一遅延の枠組みでは **外乱大小と問題セットの大小はほぼ同義**になる。加えて早い外乱の headroom は $S_p$ の準最適性回復で水増しされる交絡もある（ILS が元の $S_p$ より良い makespan に到達してしまう）。

### 3.5 文献的裏付け：先行研究も単一遅延の大きさでは作っていない

- **Zhang (2013)** は外乱大小を作っているが、**到着率 λ（sparse/dense）・新ジョブ数（20→200）** を主たる実験因子とする（故障レベル Ag も定義）。すなわち「**どれだけ頻繁に・何個・どれだけ長く**」であって「単一遅延を何分にするか」ではない。**ストリーム（複数リスケ点）が前提**。
- **Kundakcı (2016)** は外乱大小を独立変数化せず、**問題規模（op数 small/medium/large）をスケール軸**にしている。各インスタンスは固定の外乱セットを持つだけ。

固定イベント系（Kundakcı型）に立つ本研究にとって互換なスケールレバーは**問題規模のみ**であり、これは Kundakcı の設計そのものである。**先行研究も単一外乱の「大きさ」では難易度を作っておらず**、本研究の結論はこれと整合する。

### 3.6 結論

- **外乱スケール（小・大）factor を廃止**する。
- スケール（難易度）軸は **問題規模（4ベンチマーク）** に一本化する。
- 各問題には **単一の固定外乱（作業遅延1個）** を与える。ただし headroom がゼロ（縮退）にならないターゲットを選ぶ（§4）。

## 4. 外乱対象の選定（headroom 診断）

外乱が**縮退（headroom=0）**だと、どの手法も同じ解に収束し区別不能になる（mt10 の現行ターゲットがこれ）。これを避けるため、シナリオ作成時に **headroom を事前診断**してターゲットを選ぶ。

- **ツール**: `tools/measure_headroom.py`
  - `--scenario NAME` … 既存シナリオの headroom を測る
  - `--scan NAME` … `initial_gantt` の全クリティカルopをターゲットに振り headroom 分布を出す（非縮退ターゲットの探索）
- **選定基準**: headroom が十分大きい（非縮退）op をターゲットにする。
- **$S_p$ は near-optimal に生成**する（LA系は既知最適値あり、または十分な GA 世代）。これにより headroom が $S_p$ の準最適性回復で水増しされるのを防ぎ、純粋に外乱由来の再編成余地を測れる。

> ⚠ mt10 の現行ターゲット（delay60 / delay90）は headroom=0 の縮退シナリオなので **選び直し必須**。

## 6. 仮説と期待される観察（改訂）

外乱スケールに基づく旧仮説（「外乱小→ILS有利／外乱大→Memetic有利」）は、外乱大小 factor の廃止にともない **問題規模軸へ読み替える**。

| 仮説 | 根拠 |
|---|---|
| 問題規模が大きいほど $S_p$ 近傍前提が弱まり、ILS の改善成功率が低下しうる | 再スケ範囲が広く、最適解が $S_p$ から遠くなる |
| 問題規模が大きいほど Memetic+PR の集団多様性の相対価値が上がりうる | $S_p$ から遠い解の探索が必要になる |
| headroom が小さい（縮退に近い）シナリオでは手法差が出ない | headroom がアルゴリズム差の土俵そのもの |

> **補足**: 仮説の核心は「最適解が $S_p$ から**順序空間で**どれだけ遠いか」。headroom（makespan 差）はその代理指標である。厳密には ILS最適解と $S_p$ の**順序距離**も併せて測ると仮説に直結する。
